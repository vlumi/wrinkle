## Findings

1. **The latency floor is now about 65 ms end to end** against a 19 ms send round trip, so the change-data path (Debezium through vtgate, Kafka, the worker) costs about 45 ms at these rates. Before the 20 ms poll interval it was over 400 ms.
2. **At 1000/s the database saturates, not the backend.** A check at that rate with a 128-connection pool changed nothing; meanwhile the Vitess container used about five cores and the backend one. vtcombo runs vtgate, four tablets and mysqld in one container with a 1.5 GB cap. This bounds every backend the same way, so comparisons are meaningful up to 500/s on this machine; above that the protocol measures the infrastructure.
3. **CPU per thousand messages is about 1.4 s** at both working rates: at 100/s and 500/s the backend's cost per message is flat, which is what an idle-free event loop should show. Each message is one send transaction, two fan-out transactions, two pushes, and the acks.
