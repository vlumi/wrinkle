The protocol in [measuring.md](../measuring.md), every series three times, each backend from a freshly created stack (`FRESH=1`), in one session on one machine (`REPS=3 make measure-all`, 13:06 to 18:18 UTC). Medians of the three repetitions throughout. Raw runs: [go](2026-10-24-go.jsonl), [go-gateway](2026-10-24-go-gateway.jsonl), [java](2026-10-24-java.jsonl), [java-gateway](2026-10-24-java-gateway.jsonl), [ts](2026-10-24-ts.jsonl), [ts-gateway](2026-10-24-ts-gateway.jsonl), [elixir](2026-10-24-elixir.jsonl), [rust](2026-10-24-rust.jsonl).

- Commit: 7e6a395. Since [2026-10-21](2026-10-21-shapes.md): the TypeScript backend, measured for the first time; the Elixir gateway's schedulers sleep rather than spin when idle; the Java fan-out can push through APNs. No `.env` was present, so no backend pushed. The Go, Java and Rust paths under load are otherwise unchanged.
- Monoliths: Go 1.27.2, OpenJDK 25.0.4.1 and Node 26.8.1, one process each with all roles.
- Gateways: the Go, Java and TypeScript backends split into a gateway process and a services process of the same language over the internal RPC; the Elixir gateway (Elixir 1.20.4, OTP 29, Bandit) and the Rust gateway (Rust 1.99.0, tokio, axum) beside a Go services process. The measured process is the gateway.
- Machine: MacBook Pro (Mac16,5), Apple M4 Max (16 cores), 48 GB, macOS 26.7.1; Docker Desktop 4.96.3 (engine 29.9.2) with its default 16 CPUs and 8 GB. Docker Desktop was 4.96.0 on 2026-10-21.

- **Five shapes sustained 1000/s**, delivering every message in every repetition with a median p99 under 1 s: the Rust and Java gateways and the three monoliths. At 1500/s every shape saturated (63 to 82 % delivered), as on 2026-10-21; the database's limit still lies between 1000 and 1500 messages a second.
- **The Go gateway missed 1000/s on its tail.** It delivered everything, but its p99 was 0.7, 2.3 and 1.6 s in the three repetitions; on 2026-10-21 one repetition in three had such a tail. The send round trip at the median was 276 ms, against 59 ms for the Rust gateway in front of the same Go services, so the wait is on the Go gateway's side of the RPC.
- **The TypeScript gateway sustained 500/s.** At 1000/s it delivered everything, with the send round trip at 1.2 s at the median while the gateway used about 0.3 of a core. The TypeScript monolith at the same rate answered sends in 50 ms, so the queueing is in the split: the internal RPC on Node's gRPC, or the services process, whose one thread serves every gateway's calls and is not measured. Which, is not established.
- **The Elixir gateway sustained 500/s**, and at 1000/s delivered 98.3 % against 94.6 % on 2026-10-21, with its send round trip at 1.5 s at the median.
- **Below the limit the eight shapes are level**: 61 to 68 ms p50 at 500/s, p99 113 to 128 ms.
- **Past the limit the shapes fail differently.** Go, Rust and Elixir fail sends at the load generator's 10 s deadline; Java's delivered messages arrive within about 5.5 s and the rest fail, at its connection pool's 5 s timeout; the TypeScript backend keeps working on everything it accepted, so at 1500/s the monolith delivered the most (81 %) at a median of 20 s.

## CPU

Per thousand messages at 500/s. Among the gateways, Rust used 182 ms, Java 283, Go 290, Elixir 296 and TypeScript 321; among the monoliths, TypeScript 676, Go 990 and Java 1125. The TypeScript monolith used about two thirds of Go's CPU per message at 500/s and 57 % at 1000/s, with one thread for all its JavaScript. The monoliths' CPU includes the services and the fan-out and the gateways' does not, so the two groups do not compare on CPU.

Against 2026-10-21, the Elixir gateway used 27 % less, which is the schedulers no longer spinning. The other shapes, whose code did not change, used 3 to 19 % less; that bounds what a comparison across the two sessions can show.

- **The TypeScript gateway keeps the least live memory per connection**, 5 KiB, half the JVM's, growing steadily from 36 to 54 MiB. Its resident memory does not follow the connections: it was highest at 1000 in every repetition, so a straight line through the four points is nearly flat and crosses the axis above the value at 500, and neither its RSS slope nor its baseline means anything. Most of what it holds is not live: 36 of 218 MiB at 500 connections; the rest is the runtime and the heap V8 keeps after a collection, which varies between runs.
- **Rust's resident memory was steady this time**, 120 to 131 MiB at 4000 connections in the three repetitions, at the top of the 50 to 130 MiB range of earlier rounds, which is why its slope doubled.
- **The Elixir gateway's resident memory is about 35 MiB higher than on 2026-10-21** at every count, with the same slope; its live slope is unchanged. Why is not established.

## Reading it

- **The database is still the limit, between 1000 and 1500 messages a second**, and at 1000 the shapes are close enough to it that any extra wait on a send path shows as a tail: the Go, TypeScript and Elixir gateways all queue there, each on its own side of the RPC, while the monoliths of the same languages do not.
- **The TypeScript backend holds its own as a monolith**: the lowest latency of any shape at 1000/s and less CPU per message than Go's or Java's, on one thread. Split, its gateway is level with the others at 500/s and the first to queue at 1000/s.
- **Rust stays the lean gateway**: the least CPU per message and the least memory under load and idle, level with the others in latency.
